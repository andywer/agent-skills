# Proportionate closeout

Closeout answers one question: is the user-requested outcome complete enough to return honestly? It is not a retrospective on the process and does not require replaying every coordination step.

## 1. Compare the result with the objective

Re-read the user's objective and acceptance conditions. Confirm that every required item is:

- **Done** — supported by the result or adequate evidence;
- **Blocked** — with the exact missing input or external condition;
- **Deferred** — deliberately, with the consequence visible; or
- **Partial** — returned honestly as incomplete.

Optional work does not keep the run open. Delivering the result is itself part of closure.

## 2. Check the evidence that matters

Verify the result surface and the evidence supporting load-bearing claims. Reconstruct from artifacts only when the maintained orientation is stale, a handoff requires it, or the run's complexity makes memory unreliable. Do not build a new closeout ledger to prove that the old ledger was correct.

When provenance, protected promotion, execution leases, or asynchronous joins were triggered, reconcile the fields those controls actually consume. Do not accept a receipt as evidence of semantic correctness, and do not infer completion from silence.

## 3. Decide whether the assembled whole needs fresh review

Use a fresh final reviewer when integration itself is consequential and prior checks did not settle the assembled claim: high-blast-radius synthesis, protected evidence, difficult causal or quantitative interpretation, irreversible release, or a final presentation that materially changes a load-bearing claim.

Skip a fresh final reviewer when the work is direct, locally verifiable, mechanically assembled, or already covered by an adequate check whose validity survives integration. Delegation or use of another control does not by itself create a final-review obligation.

Give a required reviewer the objective, assembled result, relevant surface, and load-bearing evidence without a desired verdict. Ask whether the whole is fit for purpose, not whether the procedure was followed. Repair specific defects and re-check the changed surface; do not restart the entire review chain unless the frame or result materially changed.

If no fresh context is available for a review that materially matters, disclose the weaker verification rather than manufacturing independence.

## Stop cleanly

Return the result, the important uncertainty or blocker, and any action the user must take. Do not append a process audit unless the user requested one or it changes how the result should be trusted.
