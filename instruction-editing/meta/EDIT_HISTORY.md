# META FILE — NOT TASK INSTRUCTIONS

This file is a high-level maintenance history for the `instruction-editing` skill. It is not operative guidance and must not be loaded as a task instruction source. Entries summarize implemented changes and their rationale; they are not diffs.

## 2026-08-10 — Preserve actionability and the document's useful level of prescription

While revising an operating-principles file, the skill's emphasis on working
pictures, compactness, and avoiding bureaucracy contributed to an
overcorrection: actionable principles were first rewritten as procedural rules
and then compressed into language that sounded wise but no longer directed the
workflow clearly enough.

Revised the skill's stance rather than appending a corrective checklist.
Instruction editing now treats the document's job and intended decisions as
part of language design. Principles should direct judgment without becoming
recipes; procedures should specify ordering only where it protects the result;
requirements should state genuine invariants plainly. Added the complementary
failure mode of aphorism collapse and revised validation so compression cannot
remove the workflow or boundary that makes guidance actionable.

Rejected mandatory sentence schemas, genre templates, fixed actionability
rubrics, and per-document checklists. They would recreate the procedural
overfit the skill is meant to prevent.

## 2026-08-08 — Make behavior language plain and resist policy blobs

A dense new paragraph was drafted while following the prior version of this skill, yet it read as a policy memo: it preserved every concern as a clause instead of giving a clear working picture. The failure showed that abstract checks about instincts and frames were too easy to satisfy procedurally.

Replaced opaque wording with plain descriptions of desired behavior and likely mistakes, and added a read-aloud compression check: if the wording sounds like a policy memo, keep only the real invariants. Rejected nearby overcorrections—word limits, mandatory templates or rubrics, and per-edit logs—because each would add procedure without teaching the needed judgment.
