# Crosscut Workbench artifacts

Read this only when a Crosscut Workbench project or an explicit request needs a walkthrough mapped to local artifacts. Follow its actual contract; do not create every file merely because the vocabulary is available.

Possible mappings:

- `REQUEST.md`: the user's walkthrough question.
- `CONTRACT.md`: adopted scope, layers and evidence boundaries.
- `TRACE_IR.yaml` or `PROJECTION_GRAPH.yaml`: a requested structured account of events, claims, relationships and evidence.
- `INSPECTOR.html` or `PROCESS_INSPECTOR.html`: an inspection surface when rendering is useful.
- `WEAKNESSES.md`: consequential critique findings.
- `REPAIR_PROPOSAL.md`: an in-scope repair or further evidence proposal.

A TraceIR can suit a causal, layer-oriented process; a projection graph can suit an argumentative or branching inquiry. Neither is required for an ordinary explanation. Keep observed sources, explanatory inference and missing evidence distinct in whichever representation the project uses.
